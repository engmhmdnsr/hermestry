# Hermes Mobile on-device: consolidated audit 2026-09-29

Method: 11 specialist subagents in 3 waves (3 code audits, 5 UX scopes on real device
screenshots, 3 design critics). REPORT-ONLY: no code was edited. Every claim was to be
grep-verified; rejected claims are listed at the end. Rolling reports were sent to the user
after each wave. Findings are deduplicated across waves.

Device evidence: 7 screenshots in %LOCALAPPDATA%/hermes/cache/scratch (ux-*.png), all
captured with the app foreground. Three files were proven wrong by a pixel scan of the
bottom nav (see REJECTED). Gate state: `node scripts/verify.mjs` = PASS 8/8, 87/87.

Severity counts after dedupe: P0 5, P1 22, P2 ~55, P3 ~45.

---

## P0 (security and lying UI, fix first)

1. App lock gate never re-arms | App.tsx:82,238 + HermesContext.tsx:1122,1131 |
   `isUnlocked` is only ever set true, so lockNow() and backgrounding call lockSecrets()
   only. Settings, auto-approve and the App-Lock switch stay usable while the toast says
   "App locked". | Drive the gate from vaultUnlocked; reset isUnlocked in lockNow and in
   the visibility handler.
2. Native mirror writes are fire-and-forget | HermesContext.tsx:887,989,1007 |
   provider creds and the autostart flag the BootReceiver reads are pushed with
   `.catch(addLog)` while settingsSaveState still reaches `saved`, so saveThenToast can
   announce success when native prefs never changed and logs are only exported through an
   unmounted panel. | Await the mirror and fold rejection into settingsSaveError so the
   existing banner and Retry cover it.
3. Green "Connected" while the key is rejected | Header.tsx:130-175, HomeTab.tsx:113,
   HermesContext.tsx:1594-1606, SettingsTab.tsx:1640,1645,2276 | The header probes five
   signal names no module ever sets and never reads gatewayFailureKind, while
   markGatewayUnauthorized sets gatewayFailed without clearing `connected`. Screenshot
   evidence: header pill green Connected next to "Invalid gateway API key". |
   One statusState feeding header, Home hero and Settings card.
4. Keystore fallback stores secrets in cleartext with no warning | SecurePrefs.kt:40,133 |
   isFallback() has zero callers and putString succeeds, so lastError stays null and
   server_key/provider_key land in plaintext prefs, contradicting the contract at
   lines 17-20. | Expose fallback through status/startupInfo with a blocking banner, or
   refuse secret writes while fallback is true.
5. Server-key guard never re-reads storage | Bootstrap.kt:620-625,
   MobileGatewayService.kt:537 | The guard checks the in-memory minted value; a write that
   does not persist passes it and the gateway starts without API_SERVER_KEY. |
   Re-read SecurePrefs after putString and throw if blank.

## P1 (correctness and first impression)

6. Stale stream cleanup clobbers the new turn | HermesContext.tsx:2794 |
   A cancelled turn's finally clears streamingRef/abortControllerRef/activeRunId, so after
   stop-then-send the new turn is unstoppable and a second send is accepted. | Per-turn
   token; bail from finally unless refs still point at that turn.
7. stopStream writes its verdict too late | HermesContext.tsx:2543-2555 |
   Reads lastAgentMsgIdRef and writes stopped meta after the await, landing on the next
   turn. | Capture ownership before the await and drop the writes if the turn changed.
8. One failed save poisons every later save badge | SettingsTab.tsx:977 |
   awaitSaveOutcome returns ok:false whenever a previous attempt's error is still in
   settingsSaveState. | Require `sawSaving` before trusting state === 'error'.
9. Model switch from the chat sheet never restarts the gateway | ChatTab.tsx:2105 vs
   SettingsTab.tsx:1043 | The on-device gateway reads provider and key only at start, so
   the process keeps the old provider. | Route through applyProviderConfig restart path.
10. Start failure after a successful install shows "Nothing was installed" |
    HermesContext.tsx:1832, OnboardingWizard.tsx:501,630 | install=FAILED is reused for
    start timeouts, so the wizard and Home print false copy after a 305MB image installed
    fine. | Split start-failure state with its own copy and CTA.
11. Transitional native states never reach the UI | HermesContext.tsx:1945,
    HermesGatewayPlugin.kt:283 | INSTALLING/CHECKING/STARTING/STOPPING are unhandled, so a
    relaunch mid-install shows "Not set up / Set up Hermes" and wizard guards never arm. |
    Map transitional states to install=INSTALLING in applyState.
12. Raw loopback address printed in the UI | SettingsTab.tsx:1645,2272 |
    Gateway card and section subtitle show 127.0.0.1:8080 as user-facing status text. |
    Replace with plain copy such as "Local service on this phone".
13. Chat reads as a terminal log | ChatMessageBubble.tsx:222,316 | The identity row
    paints empty (no sender, no model, no clock) and assistant prose renders in
    `t-body font-mono`, so hierarchy between prose and code disappears. | Always render
    the sender label and clock; prose in the app sans face, mono only in fences.
14. Android back tears the drawer apart wrongly | overlayStack.ts:36, SessionsDrawer.tsx:93 |
    Back pops the drawer entry while the handler only closes an inner menu, so the next
    back jumps Home with the drawer open and a third back exits over it. | Register inner
    dialogs as their own overlays, or re-register the drawer when only an inner layer
    closed.
15. App Lock can be disabled with a second tap | SettingsTab.tsx:1894-1906 |
    appLockDesc promises PIN unlock but disabling needs no PIN. | Require
    unlockSecrets(pin) before committing appLockEnabled:false.
16. Home CTA on a failed install always says "Try setup again" | HomeTab.tsx:420,
    gatewayState.ts:189 | The same state can be started from Settings (canStart true) but
    Home only offers the install path. | Derive the CTA from gatewayState.
17. Hero status title clips to "Hermes is run..." | HomeTab.tsx:440,453 | dot + title +
    separator + a max-w-[140px] pill in one row. | Title on its own line, model pill below
    (also removes the second clip of the model name).
18. Surfaces are one flat field | index.css:20-23,243-244 | card over bg is 1.05:1, .edge
    composites to 1.23:1, elev-1 is used once and elev-2's black shadow lands at 1.03:1. |
    Surface ladder bg #090B14 / card #1A2140 (1.25:1) / card-subtle #232B52, border
    indigo 0.30 alpha (1.60:1); depth from tone plus a top hairline, shadows for sheets
    only.
19. Accent colour carries six jobs | 148 refs across 20 files | active tab tint, primary
    fills, focus ring, pulse dots, links and pills all share --app-accent. |
    Split roles: fill #4F46E5, accent text and active nav #A5B4FC, focus = outline only,
    links = #7DD3FC reserved for information.
20. Primary button text below AA | index.css:56, ChatTab.tsx:1500 | white on #6366F1 is
    4.47:1 at t-caption 12px/600. | Fill #4F46E5 (6.29:1), label t-label 13px/600,
    min-height 44px.
21. Tabs do not share a left edge | App.tsx:339 vs 313,360,379, ChatTab.tsx:1353 |
    Chat insets 12px while the others inset 16px. | px-4 (16px) on every tab.
22. Jobs list sits below the create form | JobsTab.tsx:738 | Status chips and next-run
    rows are below the fold on first open. | Lead with the list; collapse creation behind
    one "Schedule a task" button.
23. "Check connection" goes where connection state is not shown | App.tsx:324,
    HomeTab.tsx:634, SettingsTab.tsx:543 | Routes to the top of Settings with the details
    disclosure collapsed. | Open Settings with showGatewayDetails true (or rename the row).
24. Core paths have zero tests | MobileGatewayService.kt, Bootstrap.kt, SecurePrefs.kt,

25. The acceptance gate is not reproducible from git | scripts/verify.mjs, tests/ are
